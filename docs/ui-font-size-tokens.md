# UI font-size tokens

Font sizes live in `app_front/css/tokens.scss` as `--cr-font-size-*` custom
properties. `--cr-text-*` is reserved for colours; never use it for sizing.

There are two layers on purpose:

1. a new trimmed scale for Settings and new screens;
2. a legacy exact-value layer for chat, sidebar and shared recipes, so those
   screens can be moved onto tokens with zero visual change.

## New scale (Settings and new screens)

| Token | Value | px at 16px root | Typical use |
| --- | --- | --- | --- |
| `--cr-font-size-xs` | `0.72rem` | 11.52px | captions, badges, meta lines |
| `--cr-font-size-sm` | `0.8rem` | 12.8px | form controls, field labels, hints |
| `--cr-font-size-md` | `0.85rem` | 13.6px | secondary text, tab labels |
| `--cr-font-size-lg` | `1rem` | 16px | default body copy |
| `--cr-font-size-xl` | `1.125rem` | 18px | page and dialog titles |

The scale is matched to the shared form primitives:

- `cr-bar-input`, `cr-bar-select`, `cr-bar-textarea` and `cr-checkbox` use
  `0.8rem`, i.e. `--cr-font-size-sm`.
- `cr-bar-button` uses `0.82rem` — the one known off-scale primitive. It sits
  between `sm` and `md`. Do not snap it to the scale silently; that would change
  rendering and needs a deliberate visual review. No token is added for it so
  the off-scale value stays visible in the component.

Use the new scale only for Settings and screens written from now on. Do not use
it to restyle chat or the sidebar.

## Legacy exact-value layer (chat, sidebar, shared recipes)

Each token aliases one literal `font-size` value found in:

- `app_front/css/features/chat/*.scss`
- `app_front/css/features/sidebar/*.scss`
- `app_front/css/cr-recipes.scss`

The list is generated by grepping those files, not guessed. It currently has 31
distinct values (excluding `inherit`). One token per distinct value; values are
never collapsed. In particular `0.8rem` and `0.82rem` stay as two separate
tokens because both are used heavily and must keep their exact sizes.

Naming:

- rem values drop the unit and the decimal point, keeping the leading zero:
  `0.72rem` → `--cr-font-size-legacy-072`, `1.1rem` → `--cr-font-size-legacy-11`.
- non-rem values keep a unit suffix:
  `13px` → `--cr-font-size-legacy-13px`, `12.5px` → `--cr-font-size-legacy-12-5px`,
  `0.92em` → `--cr-font-size-legacy-092em`.

These tokens must not be used in new UI. They exist only for the chat/sidebar
migration step.

Excluded on purpose: `font-size: inherit` (two declarations in the chat
partials). It is a keyword, not a size, so a token would add no value.

Absolute px values stay px and em values stay em in the legacy layer. Converting
them to rem would only match at the default 16px root size; with a user-changed
root size, `12px` and `0.75rem` render differently. Legacy tokens must preserve
the authored value exactly.

Other feature partials (git, files, todo, settings, layout) are outside this
layer for now. Add a legacy token when one of those screens is migrated.

## Casing convention

- **Sentence case** for labels, buttons, tabs, menu items, field labels, hints,
  empty states and dialog actions: `Workspace path`, `Save changes`, `Add
  folder`. Capitalise only the first word and proper nouns.
- **Uppercase only for small section headings / eyebrow labels** — short
  (one to three words), letter-spaced and muted, e.g. the existing
  `.todo-section-title`, `.header-branch-title` and `.harness-health-subtitle`.
  Use `text-transform: uppercase` in CSS rather than uppercase literals in
  markup, so the underlying text stays sentence case.
- Never uppercase full sentences, body copy, button labels or form values.

## px → rem rule

- Reference: `1rem = 16px`. Convert with `rem = px / 16`: 11px → 0.6875rem,
  12px → 0.75rem, 13px → 0.8125rem, 18px → 1.125rem.
- New font sizes are written in rem, through the new scale whenever possible.
- px is allowed only for borders and hairlines, media-query breakpoints, fixed
  sub-pixel outlines, and the legacy px aliases above. Do not add a new px font
  size to UI code.

## Spacing

There is no `--cr-gap-*` family and none should be added. Use the existing
`--cr-space-1` … `--cr-space-6` tokens for gaps, padding and margins.

## No-change proof

Compile the stylesheet one-shot before and after a change and diff the output:

```bash
./node_modules/.bin/sass --no-source-map app_front/css/app.scss /tmp/before.css
# apply the change
./node_modules/.bin/sass --no-source-map app_front/css/app.scss /tmp/after.css
diff -u /tmp/before.css /tmp/after.css
```

When only tokens are added and no rule consumes them yet, the diff must contain
only added custom-property lines: zero removed or changed declarations. When a
rule is later moved onto a token, the proof is either byte-equivalence of the
computed value or a token=old-value table (the CSS text differs by `var(...)`,
the rendered size does not). Computed-style checks use the project Playwright
configs (`playwright*.config.js`). Screenshots alone are not proof.
