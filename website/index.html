Code from wherever you are.

Cretli puts a live terminal, AI agent chat, and your own developer tools in a self-hosted PWA that you can reach from your phone.

DocumentationInstallGitHub

Features

A small, self-hosted control room for the work that normally keeps you at your desk.

Mobile vibe coding

Steer agents, review diffs, and keep the live terminal close while you are away from your desk.

Remote agent control

Prompt, inspect tool calls, and manage shared sessions through one lightweight web UI.

Pluggable backends

Connect OpenCode, OpenRouter, Mistral, Cursor SDK, CodeBuddy, DeepSeek, Qwen, or Codex.

Self-hosted tools

Your server, workspace, terminal, files, and git. No hosted workspace is required.

Built-in browser

Inspect and drive a server-side Chromium session from the Browser panel when the runtime is available.

One live session

Use the same chat and terminal from multiple devices with updates broadcast in real time.

New in 0.5.0

  • Workspace registry tools: list, add, and remove projects through the wsreg_* MCP tools without editing configuration files.
  • Bulk integration over MCP: integrate_next is now the preferred call for scoped batch integration.
  • Tree-aware TODO start: a todo under an ancestor with an approved plan is executed instead of re-planned. See Todos.
  • Prepare over MCP: todo_integration action prepare builds the worktree result for integration.
  • Credit ledger and forecast: prepaid balances, DeepSeek balance readings, and runway alerts in Usage. See Settings.
  • Audited review recheck: delegation_start records the allow_recheck override and shows it in delegation rows.

Quick start

Node.js

git clone https://github.com/cretli/cretli.git
cd cretli
npm ci
npm run build:front:prod
npm start

Docker Compose

export CRETLI_SETUP_TOKEN="$(openssl rand -hex 16)"
docker compose up --build

Open https://localhost:3011 and follow first-run setup. See Docker details and security basics.

Security: Cretli exposes a full shell as your user. Keep the default localhost bind where possible, use HTTPS and a password for trusted LAN access, and never expose it directly to the public internet. See security basics and read the security policy before deployment.
